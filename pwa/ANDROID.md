# Claw2 Android

Настоящий документ описывает мобильное приложение claw2 для Android: как оно
устроено, где хранит данные, как общается с языковой моделью и как собирается.
Он дополняет [README.md](README.md), где приведены краткие команды и описание
онбординга.

## Принципы

Приложение автономно: весь агент живёт внутри установочного пакета, а не на
стороне сервера. Движок агента написан на TypeScript и исполняется внутри
WebView; разговор идёт напрямую с API языковой модели — облачного провайдера
или локального сервера в домашней сети (LM Studio, Ollama, llama.cpp).
Разговоры, вложения и долговременная память остаются на устройстве, в
локальной базе IndexedDB. Шлюз claw2 (`src/gateway` серверной части) в
мобильном сценарии не участвует.

Из этого следуют несколько решений, принятых при проектировании:

- **Capacitor вместо нативной разработки.** Интерфейс не переписывался
  заново на Kotlin: приложение переиспользует React-код мобильной
  веб-версии (`pwa/src`), поэтому один и тот же экран работает и в
  браузере, и в WebView.
- **Без авторизации.** Это персональный агент на личном устройстве:
  ни учётных записей, ни паролей, ни сопряжения. Ключ модели вводится один
  раз при первом запуске и хранится локально.
- **Без встроенного Node.js.** Серверное окружение в пакет не переносится;
  всё, что требует Node, остаётся в настольной версии.
- **Единый визуальный язык с настольной версией:** тёмная палитра в оттенках
  серого (`#202022`, акцент `#a0a0a6`), шрифт Inter встроен в пакет — внешние
  запросы к Google Fonts не выполняются. Иконка и заставка — адаптивные,
  на тёмном фоне.

## Как устроено

| Часть | Где | Роль |
|-------|-----|------|
| Конфигурация Capacitor | `capacitor.config.ts` | Идентификатор приложения `app.claw2.mobile`, каталог веб-сборки `dist`, поведение клавиатуры и краевых отступов. |
| Gradle-проект | `android/` | Нативная оболочка: манифест (микрофон, точные будильники), темы, иконки. Проект сопровождается вручную — повторная генерация не предполагается. |
| Точка входа | `src/main.tsx`, `src/App.tsx` | Загрузка интерфейса; в браузере регистрируется service worker, в приложении — нет. |
| Движок агента | `src/engine/` | Вся логика: настройки, хранилище, клиент модели, инструменты, память, напоминания. |
| Интерфейсный слой | `src/api/` | Единое представление для экранов: отправка сообщений, история, файлы, распознавание речи. |
| Экраны | `src/components/` | Лента чата, список чатов, настройки, онбординг, ячейки медиа и диаграмм. |

Основные модули движка:

| Модуль | Назначение |
|--------|------------|
| `settings.ts` | Все настройки приложения в `localStorage`; реестр провайдеров модели. |
| `db.ts` | IndexedDB `claw2-mobile`: чаты, сообщения, память, файлы, напоминания. |
| `llm.ts` | Прямой OpenAI-совместимый клиент: потоковый обмен, вызовы инструментов, список моделей, эмбеддинги. |
| `agent.ts` | Ход диалога: системный промпт, цикл инструментов, проверка достоверности. |
| `tools.ts` | Инструменты: вычисления, поиск, чтение страниц, изображения, документы, память, напоминания. |
| `cells.ts` | Разбор встроенных ячеек `[CELL …]` и обеззараживание HTML. |
| `context.ts` | Удержание контекста: краткий пересказ ранее сказанного + окно последних сообщений. |
| `honesty.ts` | Политика честности и опциональная проверка ответа по собранным материалам. |
| `notifications.ts` | Напоминания через системные уведомления и будильники Android. |
| `docs-extract.ts` | Чтение входящих PDF, XLSX и DOCX на устройстве. |
| `files.ts`, `mime.ts` | Файлы сессии и восстановление типов файлов по расширению. |
| `now.ts` | Подстановка текущих даты, времени и часового пояса в контекст модели. |

## Диалог с моделью

**Первый запуск.** Экран настройки соединения показывается один раз; признак
завершённости — флаг `onboarded` в настройках. Мастер запрашивает три поля:
адрес API, ключ и модель (список моделей запрашивается с сервера и даётся с
поиском; идентификатор можно ввести и вручную). Если позднее соединение
перестанет работать, приложение не возвращает к мастеру: в чате появляется
предупреждение «Модель не настроена» со ссылкой в настройки.

**Провайдеры.** В настройках есть раздел «Провайдеры» — список соединений
с моделями. Каждая запись включает имя, адрес, ключ, модель, модель-роутер
и свободную заметку о возможностях; активный провайдер выбирается касанием.
Соединение, созданное при первом запуске, попадает в этот же список.

**Роутер.** При наличии двух и более провайдеров можно включить режим
роутера: лёгкая модель-диспетчер один раз за ход читает диалог и список
кандидатов и решает, кто ответит. Если выбранный провайдер не ответил до
первого токена, запрос автоматически переходит к следующему; начавший
отвечать повторно не вызывается. За чатом можно закрепить конкретного
провайдера — тогда роутер пропускается. Под каждым ответом показывается
строка «модель · провайдер»: касание по ней закрепляет или открепляет
исполнителя.

**Формат обмена.** Запросы идут на `{адрес}/chat/completions` в режиме
потоковой передачи (SSE). У ряда моделей «размышления» можно отключать на
уровне запроса — приложение посылает соответствующие флаги в зависимости
от настройки «Размышления» и модели (deepseek, minimax). Локальным адресам
разрешена работа без ключа. Список моделей — `GET {адрес}/models`,
эмбеддинги — `POST {адрес}/embeddings`.

**Достоверность.** Политика честности в системном промпте требует опираться
на собранные материалы и память, признавать неуверенность и не выдумывать
ссылки. Дополнительно можно включить проверку ответа: черновик перечитывается
против результатов инструментов, и неподтверждённые утверждения переписываются.
Если проверка не удалась, ответ всё равно уходит — в исходном виде.

## Настройки

Все настройки живут на устройстве и правятся на экране «Настройки»:
подключение к модели (базовый адрес, ключ, модель, режим размышлений),
список провайдеров и режим роутера, персона и имя ассистента, память и
сервис эмбеддингов, поиск (Tavily, SearXNG или совместимый эндпоинт),
генерация изображений, удержание контекста, достоверность и голос.
Изменения вступают в силу сразу, без перезапуска.

## Голосовой ввод

Кнопка удержания в поле ввода записывает речь и отправляет её на сервис
распознавания — любой OpenAI-совместимый адрес (`{адрес}/audio/transcriptions`),
ключ и модель настраиваются в разделе «Голос». Расшифрованный текст
подставляется в сообщение; запись выполняется с микрофонного разрешения,
запрошенного системой при первом использовании.

## Инструменты агента

Модель распоряжается набором инструментов, описанным в системном промпте:
вычисления (mathjs), поиск в интернете с резервным вариантом через
DuckDuckGo, чтение страниц, генерация изображений (Stable Diffusion),
создание документов DOCX, работа с файлами сессии, память
(`remember`/`recall`), напоминания. Инструмент вызывается внутри одного хода
до шести раз; результаты собираются и используются как опора для ответа.

На устройстве сетевые запросы инструментов исполняются нативным мостом
(`CapacitorHttp`) — вне движка WebView, где ограничения CORS не действуют;
у каждого запроса есть тайм-аут, поэтому зависший сайт не останавливает
диалог. Полноценное потоковое общение с моделью идёт через обычный WebView-запрос:
провайдер должен разрешать CORS (для LM Studio и Ollama это настраивается
на их стороне).

## Вложения и файлы

К сообщению прикладывается до двадцати файлов, каждый до 15 МБ. Изображения
в читаемых форматах (PNG, JPEG, WEBP, GIF) уходят модели как зрение;
текстовые файлы вписываются в сообщение; PDF, XLSX и DOCX разбираются
прямо на устройстве, и их содержимое попадает в промпт (до ~60 тысяч
знаков на файл). Сканы PDF и нечитаемые файлы честно помечаются — модель
не делает вид, что прочитала их. Тип файла восстанавливается по расширению,
если Android вернул пустой.

Файлы, созданные в разговоре, хранятся в базе сессии и показываются на
вкладках «Изображения» и «Документы» вместе с вложениями. Выгрузка идёт
через системную панель «Поделиться» — файл передаётся как файл (через
FileProvider), а не текстом. Удаление чата удаляет и его файлы. Экспорт
разговора в Markdown — кнопка в списке чатов, тот же механизм передачи.

## Память и контекст

Долговременная память — отдельное хранилище IndexedDB. Факт записывается
инструментом `remember`; перед каждым ходом уместные записи подмешиваются
в контекст (`recall`). При настроенном сервисе эмбеддингов поиск идёт по
смыслу (косинусное сходство), без него — по ключевым словам.

Длинные разговоры не растут бесконечно: старая часть переписывается кратким
пересказом, который попадает в системный промпт, а последние сообщения
остаются целиком. Пороги — в настройках контекста (по умолчанию: окно
10 ходов, суммаризация от 12 сообщений, 6 последних сообщений вне окна).
Пересказ делается фоном после ответа и его не задерживает.

## Напоминания

Инструменты `set_reminder` и `cancel_reminder` опираются на системные
уведомления Android. Напоминание выдаётся точно в срок, пока разрешены
точные будильники (для этого в манифесте объявлены `USE_EXACT_ALARM` и
`SCHEDULE_EXACT_ALARM`); без разрешения — с дрейфом в минуты. Если
напоминание осталось без внимания, оно повторяется по нарастающей: через
2 часа, затем с шагами до 22 часов; каждый шаг — отдельное уведомление со
своим номером. Касание по уведомлению отмечает напоминание прочитанным.
Смахивание повтор не отменяет — следующий шаг придёт по расписанию.
Спустя сутки напоминание истекает и остаётся в истории. Разрешение на
уведомления запрашивается при первом напоминании.

## Интерфейс и адаптивность

Приложение одинаково уместно выглядит на обычном телефоне и на складном
экране, потому что интерфейс собран из одного набора панелей — списка
чатов, содержимого открытого разговора и панели вкладок. Панели существуют
всегда, меняется лишь их расположение: пока ширина окна меньше 640
пикселей, видна одна панель; на широком экране — обе сразу (раскрытый
Pixel Fold предоставляет около 671). Диаграммы и таблицы следят за
размерами своей области и перестраиваются под новую ширину.

Из этого свойства следует главное для диалога: экран не пересоздаётся
целиком. Поворот устройства, складывание и раскладывание меняют только
компоновку, и печать ответа продолжается с того же места. Манифест
объявляет изменение размеров экрана конфигурацией, с которой Android
справляется без перезапуска приложения.

Системное поведение подстраивается двумя плагинами: статус-бар затемняется
и подкрашивается в цвет фона, а при открытой клавиатуре WebView сжимается
(на Android 15 и новее штатный `adjustResize` в сквозном режиме не
работает — за это отвечает `@capacitor/keyboard` с
`resizeOnFullScreen`). Поле ввода — плавающая панель с матовым стеклом;
лента прокручивается под ней. Ответы модели печатаются чистым текстом без
«облачка», реплики пользователя — компактные стеклянные плашки; шапка и
панель вкладок полупрозрачные с размытием.

## Особенности платформы

Несколько свойств Android и WebView определили детали реализации; они
перечислены здесь, чтобы поведение приложения не казалось произвольным.

- **Таймеры в фоне.** В скрытом WebView `requestAnimationFrame` не срабатывает,
  поэтому приходящие фрагменты ответа выводятся через `setTimeout` (при
  скрытом документе — немедленно).
- **Неполные сведения о файлах.** Android часто возвращает файлы без
  MIME-типа; тип восстанавливается по расширению, а в «зрение» отправляются
  только форматы, читаемые моделями. Атрибут `capture` у поля выбора не
  используется — иначе открывается только камера, без галереи.
- **Клавиатура.** На свежих версиях Android сжатие экрана под клавиатурой
  делает плагин клавиатуры, а не системный режим окна.
- **Передача файлов.** Файлы передаются только через параметр `files`;
  путь в `url` превращается в текстовое сообщение без самого файла.
- **Открытый HTTP.** Приложение разрешает незащищённый HTTP-трафик:
  локальные серверы моделей в домашней сети (LM Studio, Ollama) обычно
  работают без TLS. Для облачных провайдеров используйте адреса HTTPS.
- **Незакрытые ячейки.** Модель не всегда завершает блок `[CELL]`
  закрывающей меткой; парсер восстанавливает границу по содержимому, а
  HTML ячейки проходит фильтр разрешённых тегов и атрибутов перед
  отрисовкой.
- **Мост вместо глобального перехвата.** Глобальное включение
  `CapacitorHttp` буферизует ответы и ломает потоковую передачу модели,
  поэтому нативный мост вызывается точечно, только для запросов
  инструментов.

## Сборка и запуск

Среда: Node.js 20+, Android Studio (в сборке используется входящий в неё
JBR), Android SDK. Из каталога `pwa`:

```bash
npm install

npm run dev             # веб-вариант в браузере: http://localhost:5174/pwa/
npm run build           # веб-сборка
npm run build:android   # веб-сборка для приложения (пути от корня)
npm run android:sync    # сборка + синхронизация Capacitor
npm run android:apk     # отладочный APK
npm run android:release # релизный APK (подписанный при настроенном ключе)
npm run android:open    # открыть Gradle-проект в Android Studio
```

Готовые пакеты: `android/app/build/outputs/apk/debug/` и
`…/apk/release/`. Установка на устройство: `adb install -r <файл.apk>`.

Версию пакета можно задать без правки `build.gradle` — переменными
окружения (для магазина версионный код должен нарастать):

```bash
CLAW2_VERSION_CODE=3 CLAW2_VERSION_NAME=1.0-beta1 \
CLAW2_APK_NAME=claw2-mobile-beta1 npm run android:release
```

Иконки и заставку пересобирает утилита Capacitor из исходника
`assets/icon.png`:

```bash
npx @capacitor/assets generate \
  --iconBackgroundColor "#202022" --iconBackgroundColorDark "#202022" \
  --splashBackgroundColor "#202022" --splashBackgroundColorDark "#202022"
```

Утилита правит и `public/manifest.json` — ссылки на иконки после неё
возвращают вручную.

Перед коммитом принято проверять типы и сборку (`npx tsc -b && npm run
build`) и выполнять модульные тесты (`npm test` — Vitest; покрывают разбор
ячеек, чтение документов, типы файлов, экспорт и другие модули движка).

## Релизная подпись

Релизный ключ хранится в `android/claw2-release.keystore`, пароли — в
`android/keystore.properties`; оба файла исключены из репозитория. Сборка
читает свойства, если файл на месте; без него релизный пакет собирается
без подписи. Потеря ключа означает невозможность обновлять приложение
поверх установленного — новый ключ система считает другим приложением.
Храните резервные копии обоих файлов вне репозитория. При переходе с
отладочного пакета на релизный отладочный сначала удаляют: подписи разные,
а вместе с приложением удалятся и его разговоры — заранее сделайте
экспорт.

## Границы мобильной версии

Мобильная версия сознательно не включает серверные возможности настольной:
исполнение навыков в песочнице, встроенный браузер, телефонные звонки,
боты Telegram и VK, многопользовательский доступ и ядро HSS. Мобильному
агенту эти механизмы не нужны: разговоры целиком хранятся на устройстве,
а вычислительные задачи решаются инструментами и моделями.

Напоминания и чтение входящих документов закрывают большинство бытовых
сценариев без сервера.
